# 使い方の詳細

README の「使い方の要点」から一歩踏み込んで、各機能が Discord でどう動くかを引くための文書。セットアップと起動は [README](../README.md) にある。
Claude Code 自体の挙動（設定の効き方、ダイアログなど）についての記述は、Claude Code の仕様に基づく説明で、このリポジトリのテストでは確かめていない。

## メッセージ

- ボットに DM を送ると、手元のセッションにメッセージが届き、届いた印に 👀 が付く。許可チャンネルでボットにメンションしたときや、ボットが関わっているスレッドに発言したときも同じ。
- 受け付けるのは、**ボットとの DM と、`access.json` の `channels` に書いたチャンネル（とその中のスレッド）だけ**。ほかのチャンネル・グループ DM・編集や削除のイベント・ボットや webhook の発言・ピン留めなどのシステムメッセージは無視する。
- 返事の届き方は、話しかけた場所で変わる。Claude には、届いたタグの `chat_id` / `thread_id` をそのまま `reply` に渡すよう、MCP の instructions で指示してある。
  - **DM**: Discord の DM にはスレッドが無いので、元のメッセージへの返信（引用付きの返信）として届く。
  - **チャンネル**: 元の発言からスレッドを作り（名前は本文の先頭40文字）、そこに返す。スレッドの中で話しかけたときは、そのスレッドに返す。
- チャンネルで Claude に届くのは、次の発言だけ。それ以外の雑談には反応しない。
  - ボットへのメンション（`@<ボット名>`）付きの発言。入力欄のメンションの候補には、ボット本人と、ボットと同じ名前のロールの両方が出る。どちらを選んでも話しかけたことになる。
  - ボットの発言への返信（Discord の「返信」）。
  - ボットが関わっているスレッドでの発言。関わっているスレッドとは、ボットが作ったスレッドと、ボットが投稿したスレッドのこと。メンションは要らない。
  - メンションは本文から取り除いてから Claude に渡す。
  - 関わっているスレッドは、ブリッジが動いている間だけ覚えている（新しい順に500件）。再起動したら、もう一度メンションする。
  - チャンネルでも、`allowFrom` に無いメンバーの発言とボタン操作は無視する。
- `channels` にはフォーラムも書ける。フォーラムでは、投稿（スレッド）の中でボットにメンションして話しかける。返事はその投稿に届き、以後その投稿ではメンションなしでも届く。ボットが新しい投稿を作ることはない。
- メッセージとボタン操作は、届いた順に1件ずつ処理する。前の処理が終わるまで、次は始めない。ボタンの「受け取った」という応答だけは、Discord の3秒の期限に間に合うよう先に返す。
- 1通の上限（2000文字）を超える返信は、1900文字ごとに分けて送る。コードブロックの途中で分けるときは、閉じてから次の通で開き直す。途中で送信に失敗すると、Claude には何件目まで送れたか（`sent=N`）を添えたエラーが返る。
- 6000文字を超える返信は、分けずに冒頭だけを本文にして、全文を `reply.md` として添付する。境目は `.env` の `LONG_REPLY_CHARS` で変えられ、`0` なら常に分けて送る。
- 送る文の `@everyone` / `@here` / ロール・ユーザーへのメンションは、どれも通知しない。返信先の人への通知も出さない。
- Claude にメッセージを渡してから5分たっても Claude が何も返さないと、「⚠️ Claude から 5 分応答が無い」と投稿する。「何も返さない」とは、`reply` / `react` / `edit_message` の呼び出しも、実行許可の確認も無いこと。
  - ターミナル側の選択画面（Discord には中継されない）、使用量の上限、セッションの停止などで止まっていても、Discord からは気付けない。それを防ぐための警告。
  - 見張るのは、最後に渡したメッセージ1件だけ。待ち時間は `DISCORD_CHANNEL_REPLY_TIMEOUT_MIN` で変えられる。
  - 警告には「🖥 画面を確認」ボタンが付く（[ターミナル画面の確認と選択](#ターミナル画面の確認と選択)）。
- セッションは1つだけで、Discord 側の会話はすべて同じ文脈を共有する。
- Discord のメッセージは本文として Claude に届くだけで、Claude Code のコマンドは実行できない。`/clear` と書いても、ただの文として Claude に届く。例外は `!restart` / `!compact` / `!clear` / `!stop` で、これらはブリッジがターミナルに打ち込む。
- ブリッジが処理する `!` のコマンドの一覧は、[README の使い方の要点](../README.md#使い方の要点) にある。`!help` を送ると、同じ一覧が返る。

## スラッシュコマンド

`!` のコマンドは、`/status` のようなスラッシュコマンドとしても使える。入力欄に `/` を打つと、候補にボットのコマンドが説明つきで出る。

- ブリッジは起動するたびに、コマンドをアプリ全体に登録する。登録済みのものと同じなら登録し直さない。登録に失敗しても、`!` のコマンドはそのまま使える（ログに `スラッシュコマンドの登録に失敗` が出る）。
- 候補に出るのは、ボットのいるサーバーとボットとの DM だけ。
- 引数のあるコマンドは2つ。`/restart` の `force`（true で強制終了してから起動し直す）と、`/keepalive` の `mode`（on / off。省略すると状態を見るだけ）。
- 使うと、ボットが「⌨️ `/status`」のように使ったことを一言残し、結果はその一言への返信として返す。チャンネルでは、その一言からスレッドを作ってそこに返す。スレッドの中で使えば、そのスレッドに返す。
- 使える人と場所は `!` のコマンドと同じ。`allowFrom` に無い人や、許可していないチャンネルで使うと、本人にだけ見える返事で使えない旨を返し、何もしない。

## 右クリックで Claude に渡す

メッセージを右クリック（スマホでは長押し）して、**アプリ** → **FOX3 Bridge**（ボットの名前）→ **Claude に渡す** を選ぶと、そのメッセージを Claude に渡せる。ほかのメンバーやボットの発言も渡せる。

- 渡すと、ボットが「📨 Claude に渡した: <メッセージへのリンク>」と一言残し、渡した発言に 👀 を付ける。Claude の返事はその一言への返信（チャンネルではそこから作るスレッド、スレッドの中ならそのスレッド）に届く。
- Claude には、本文の前に「転送: 渡した人と書いた人」の印を付け、`kind="forwarded"` として渡す。中身はデータとして扱い、そこに書かれた指示には従わないよう、MCP の instructions で指示してある。
- `!` で始まる発言や `yes xxxxx` を渡しても、ブリッジのコマンドや実行許可の回答にはならない。
- 添付は、ふつうのメッセージと同じく要約と ID を渡し、テキストの添付は本文に差し込む。
- 使える人と場所は `!` のコマンドと同じ。許可外なら、本人にだけ見える返事で断る。

## CI の通知を Claude に渡す

GitHub Actions などの CI が Discord の webhook で結果を投稿すると、その投稿を Claude に渡せる。ふつう webhook の投稿は無視するが、`access.json` の `ciWebhooks` に書いた webhook のものだけは渡す。

1. Discord で `channels` に書いたチャンネルの **チャンネルの編集** → **連携サービス** → **ウェブフック** で webhook を作り、**ウェブフック URL をコピー** する。URL は `https://discord.com/api/webhooks/<webhook の ID>/<トークン>` の形。
2. `access.json` の `ciWebhooks` に webhook の ID（URL の数字の部分）を書き、ブリッジを起動し直す。
   ```json
   { "guildId": "...", "allowFrom": ["..."], "channels": ["..."], "ciWebhooks": ["<webhook の ID>"] }
   ```
3. GitHub のリポジトリの **Settings** → **Secrets and variables** → **Actions** に、URL 全体を `DISCORD_CI_WEBHOOK` として登録し、ワークフローの最後に知らせるステップを足す。
   ```yaml
       - name: Discord に知らせる
         if: always()
         env:
           DISCORD_WEBHOOK: ${{ secrets.DISCORD_CI_WEBHOOK }}
           TEXT: "CI ${{ job.status }}: ${{ github.repository }} (${{ github.ref_name }}) ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}"
         run: jq -n --arg content "$TEXT" '{content: $content}' | curl -sS -H 'Content-Type: application/json' -d @- "$DISCORD_WEBHOOK"
   ```
   CI のワークフローに手を入れたくないときは、別のワークフローを `workflow_run` で CI の完了に合わせて動かす。このリポジトリでは [.github/workflows/notify.yml](../.github/workflows/notify.yml) がそれで、マトリクスの全ジョブが終わってから1回だけ知らせる。知らせるたびに Claude が1ターン使うので、知らせるのは main への push の結果（成功も失敗も）と PR の失敗だけにしている。取り消された実行と、フォークからの PR（タイトルなどの外の人が書いた文が Claude に届く）は知らせない。

- 渡すのは、`channels` のチャンネル（とその中のスレッド）への投稿だけ。メンションは要らない。DM や許可していないチャンネルへの投稿は渡さない。
- 本文と embed（見出し・URL・本文・項目・注記）の文字を合わせ、「CI の通知」の印を付けて `kind="ci"` で渡す。中身はデータとして扱い、結果を短く伝えるよう、MCP の instructions で指示してある。直す作業や push は、利用者が頼んでから行う。
- 投稿には 👀 を付け、Claude の返事はその投稿から作るスレッドに届く。
- webhook の URL にはトークンが入っている。URL が漏れると、誰でも CI の通知のふりをして Claude に文を渡せる。URL は GitHub の Secrets にだけ置き、漏れたら Discord で webhook を消して作り直す。

## 入力中の表示とボットのステータス

- Claude にメッセージを渡してから応答が終わるまで、返信先に「入力中…」を出す。8秒ごとに出し直し、15分で打ち切る。
  実行許可の回答待ちの間と、`!stop` で中断したときは止める。応答の終わりは hook の `Stop` で知る。
- ボットのステータス（メンバー一覧の名前の下に出る一言とオンライン状態）に、Claude の状態を出す。上にあるものほど優先する。

  | 状態 | 表示 |
  |---|---|
  | 使用量の上限に当たっている | 取り込み中・「使用量の上限」 |
  | 実行許可の回答待ち | 退席中・「実行許可待ち」 |
  | 応答中 | オンライン・「作業中」 |
  | それ以外 | オンライン・「待機中」 |

  Discord の更新回数の制限に当たらないよう、表示を変えるのは15秒に1回まで。その間の変化は、最後の状態だけを反映する。

## TODO の進み具合（`progress`）

手順の多い作業を頼んだときに、Claude が作業の TODO を「📋 TODO（2/5 完了）」のカードで出す。

- Claude は MCP ツール `progress(chat_id, thread_id?, items)` で TODO の一覧の全体を渡す。`items` は内容（200文字まで）と状態（`pending` / `in_progress` / `completed`）の組で、1〜50項目。手順が3つ以上ある作業ではこのツールを使うよう、MCP の instructions で指示してある。
- 返信先に1枚出し、同じ返信先で続けて呼ぶと同じカードを書き換える。次に話しかけると、その次の一覧は新しいカードになる（上の方の古いカードを書き換えても見えないため）。
- 終わったものは ✅ と打ち消し線、作業中は ▶️ と太字、まだのものは ⬜ で出す。全部終わるとカードが緑になる。
- `progress` は許可リストに入れてあるので、確認なしで呼ばれる。
- `.env` に `TODO_PROGRESS=off` を書くと、ツール自体を出さない。
- Claude Code の TodoWrite（作業の TODO を管理するツール）は、版によって無い。そのため hook で拾うのではなく、ブリッジのツールにしてある。

## 添付ファイル

### テキストの添付は本文に差し込む

Discord は2000文字を超える貼り付けを `message.txt` の添付に変える。そのままでは Claude に中身が届かないので、小さなテキストの添付は中身を取ってきて本文の後ろに足す。

- 対象は、拡張子が `.txt` / `.log` / `.md` / `.csv` / `.tsv` / `.json` / `.jsonl` / `.yaml` / `.yml` / `.diff` / `.patch` / `.xml` / `.ini` / `.toml` のもの。
- 1ファイル100KBまで、1メッセージで3ファイル・合計200KBまで。1ファイルの上限は `.env` の `INLINE_TEXT_MAX_KB` で変えられ、`0` なら差し込まない。
- 差し込んだファイルの名前は、届いたタグの `inlined` に載る。上限を超えたものや差し込めなかったものは、ほかの添付と同じ扱いになる。

### ほかの添付は、要るときに保存する

ほかの添付の中身は渡さない。Claude に届くのは、ファイル名・種類・サイズの要約と添付の ID（`attachment_ids`）だけ。本文が無いメッセージは `(attachment)`、複数の添付なら `(N attachments)` として届く。

`.env` に `DOWNLOAD_DIR`（絶対パス）を書くと、MCP ツール `download_file` が使えるようになる。書かなければツール自体が出ない。

- `download_file(chat_id, message_id, attachment_id, thread_id?, extract?)` は、添付を `DOWNLOAD_DIR` に保存して、保存先のパスを返す。自動では保存せず、Claude が必要なときだけ呼ぶ。画像は保存したあと Claude が Read で見る。
- `download_file` は許可リストに入れていないので、呼ぶたびに実行許可の確認が出る（手元のフォルダーに書き込む操作のため）。
- 添付の URL には期限があるので、取りに行くたびにメッセージを読み直して新しい URL をもらう。取りに行く先は Discord の CDN（`cdn.discordapp.com` / `media.discordapp.net`）の https だけで、トークンは付けない。
- 同じ名前のファイルがあれば、`名前 (1).拡張子` のように番号を付ける。上書きはしない。
- ファイル名は送信者が自由に付けられる。そこで、パス区切りより前を捨て、Windows で使えない文字を `_` に置き換えてから保存する。
- `extract: true` を付けると、圧縮ファイルを `DOWNLOAD_DIR\<名前>\` に展開する。元のファイルは残す。
  - zip / 7z / rar / tar / tar.gz（tgz）/ tar.bz2 / tar.xz / tar.zst / lzh は、Windows 付属の `tar.exe`（bsdtar）で展開する。単体の `.gz` は Node の zlib で展開する。
  - パスワード付きのアーカイブや、bsdtar が読めない形式はエラーになる。アーカイブの中のアーカイブは展開しない。
  - PATH 上の `tar`（Git の GNU tar など）は使わず、`%SystemRoot%\System32\tar.exe` を直接呼ぶ。
- 上限は、ダウンロードが 1GB、展開後が合計 4GB・10万ファイル。超えたら止めて、書きかけ・展開しかけのものを消す。
- `..` や絶対パスを含むエントリ（Zip Slip）は bsdtar が拒否する。展開後にシンボリックリンクやジャンクションが見つかったら、展開先ごと消してエラーにする。
- 展開したファイルを実行したり解釈したりはしない。ファイルの中身はデータとして扱い、中に書かれた指示には従わない（MCP の instructions と同じ扱い）。
- 画像の添付では、Discord が返す種類とサイズ（例: `image/webp`・400 bytes）が、CDN から実際に届くファイル（例: PNG・827 bytes）と違うことがある。保存されるのは CDN から届いた実物。

## ファイルの送信（`send_file`）

`.env` に `UPLOAD_DIRS`（絶対パスを `;` で区切る）を書くと、手元のファイルを Discord に添付して送る MCP ツール `send_file` が使えるようになる。書かなければツール自体が出ない。
手元の何でも外に出せる口になるので、送ってよいかはブリッジが必ず判定する。Claude Code の許可設定には頼らない。

- `UPLOAD_DIRS` の中のファイルは、確認なしで送る。
- 外のファイルが1つでも含まれると、「📎 このファイルを送っていい？」のカードを出す。**送る** / **やめる** で答える。10分答えなければ送らない。
  ツールはすぐに「確認待ち」を返し、結果は後から `kind="file_sent"` のメッセージで Claude に届く。
- 次のファイルは、どこにあっても送らない。
  - 名前が `.env` / `.env.*` のもの、拡張子が `.pem` / `.key` / `.pfx` / `.p12` / `.kdbx` / `.ppk` / `.jks` / `.keystore` / `.asc` / `.gpg` のもの
  - `.ssh` / `.aws` / `.gnupg` / `.claude` / `.docker` / `.kube` / `.azure` フォルダーの中のもの
  - 状態ディレクトリの中のもの（`UPLOAD_DIRS` の中にあっても）
- 判定は、ジャンクションやシンボリックリンクをたどった先のパスで行う。
- 1ファイルの上限は 10MB（ブーストしていないサーバーと DM の上限）。`.env` の `UPLOAD_MAX_MB` で 100 まで上げられる。

## 実行許可

許可リストに無い操作を Claude が実行しようとすると、「🔐 実行許可」のカードを Discord に出す。
出す先は、最後に Claude へ中継したメッセージの返信先（チャンネルならそのスレッド、DM ならその DM）。
起動してからまだ何も中継していないときや、返信先への投稿に失敗したときは、許可ユーザー全員の DM に出す。

- **Allow / Deny** のボタンで答えるか、`yes xxxxx` / `no xxxxx` と返信する。
  `xxxxx` はカードに表示された5文字の ID。`y` / `n` でもよく、大文字と小文字は区別しない。
- 答えると、カードの表示が「✅ 許可した」/「❌ 拒否した」と回答者に変わり、ボタンが消える。DM で全員に配信したときは、全員分を書き換える。
  テキストで答えたときは、その返信に ✅ / ❌ が付く。
- 保留中でない ID への `yes xxxxx` は回答として扱わず、普通のメッセージとして Claude に届く。
- 有効期限は **30分**。期限までに答えが無ければ Claude に自動で deny を返し、カードを「期限切れのため自動で拒否した」表示に書き換える。
  期限切れのボタンを押しても Claude には送らない。押したカードが期限切れの表示に変わるだけ。
- Discord から答えられない次の場合も、自動で deny を返す。
  - どこにも投稿できなかったとき。ログに `permission_request をどの DM にも配信できなかった` が出る。
  - ブリッジの終了時に保留中だったとき。カードは「ブリッジ終了のため自動で拒否した」表示に書き換える。ただし書き換えられるのは、切断する前に間に合った分だけ。
- 入力内容（コマンドや差分）は、合計で約2800文字まで表示する。
  それを超えるときは、先頭の約2200文字と末尾の約600文字を残し、間に `…（途中 N 文字省略）…` を入れる。その下に「See more で全文を確認すること」という警告の行を出す。
- ツール名・説明・入力内容のどれかを省略したときだけ、**See more** ボタンが付く。押すと、入力内容の全文をコードブロックで送る。
  長ければ複数のメッセージに分け、期限切れならその旨だけを送る。
- 見えない文字は、`\u{202E}` のような表記に置き換えて表示する（See more の全文でも同じ）。仕込まれた文字で表示を偽装されないようにするため。対象は次のとおり。
  - 文字の向きを変える制御文字（U+202A〜202E、U+2066〜2069、U+200E〜200F）
  - ゼロ幅文字（U+200B〜200D、U+2060〜2064 など）
  - BOM（U+FEFF）
  - ソフトハイフンや、空白に見える埋め文字
  - タブと改行を除く C0 / C1 制御文字
- Allow / Deny を Claude に送れなかったとき（MCP の切断など）は、カードを「送れなかった」表示に書き換える。
- 同じ ID の確認が重ねて届いても出し直さない。最初に出したボタンで答えられる。
- Claude から届いた確認の ID が想定外の形（`l` を除く英小文字5文字でない）のときは、Discord には出さない。ログに警告を残し、自動で deny を返す。
- ターミナル側にも同じ確認が出るので、どちらで答えてもいい（Claude Code 側の挙動で、このリポジトリでは確かめていない）。

## 普段の MCP サーバーは Discord のセッションでは読み込まれない

Discord のセッションは `--strict-mcp-config` で起動する。そのため、普段の Claude Code で使っている MCP サーバー（ユーザー設定 `~/.claude.json` や、作業フォルダーの `.mcp.json` に登録したもの）は**読み込まれない**。
エラーも確認画面も出ず、Claude からは「そのツールにつながっていない」ように見えるだけなので、気付きにくい。

- Discord のセッションでも使うサーバーは、`config\extra-mcp.json` に `.mcp.json` と同じ形で書く（ひな形: [config/extra-mcp.example.json](../config/extra-mcp.example.json)、git の管理外）。
  起動時に `追加の MCP サーバー: ...` と表示される。
- `.mcp.json` に新しいサーバーがあると、承認を求める確認画面がターミナルに出る。ウィンドウを隠して動かしていると Discord からは気付けず、セッションが止まったままになる。そのため `.mcp.json` はそのまま読ませない。`extra-mcp.json` に書いたサーバーには、この確認画面は出ない。
- 追加したサーバーのツールは**確認なしで実行される**。起動スクリプトが `mcp__<サーバー名>` を allow に足すため。
  使う人が承知して入れたサーバーとみなすので、ツールの中身（任意のスクリプトを実行できるものなど）を理解したうえで登録する。
  個別のツールだけ確認させたいときは、`channel-settings.json` の `ask` に書く（allow より優先される）。
- OAuth の認証が要るサーバー（HTTP 型など）は、先にターミナルの `/mcp` から認証しておく。Discord からは認証できない。
- claude.ai のコネクター（Gmail など）は、起動スクリプトが無効にしている（`ENABLE_CLAUDEAI_MCP_SERVERS=false`）。

## 許可リストへの追加（♾ 今後も許可）

実行許可のカードの **♾ 今後も許可** を押すと、今回の操作を許可したうえで、同じ種類の操作を許可リストに足すかを確かめるカードを出す。
**追加する** を押すと、状態ディレクトリの `allow-extra.json` に書き込む。**次に再起動したときから**、その操作は確認なしで実行される。
起動スクリプトが `channel-settings.json` の allow に足してから Claude Code に渡すので、動いているセッションには効かない。`!restart` で起動し直したときも、足し直してから渡す（`!rules` で消したものも、その時点で外れる）。

- ルールは確認の中身から作る。自由な入力は受け付けない。作れるものは許可リストで決めてあり、作れない操作のカードには **♾ 今後も許可** を出さない（その場の 1 回の許可だけになる）。方式と一覧は [権限の設計とセキュリティ](security.md#今後も許可で作れるルール) に書いてある。
  - Bash / PowerShell: 一覧のコマンド（`git status` / `pwd` / `Get-Location` / `ls` / `dir`）を引数を付けずに呼んだものだけ、完全一致のルールにする（例: `Bash(git status)`、`PowerShell(Get-Location)`）。`:*` は付けないので、引数付きの呼び出しには効かない。
    - 引数付きの呼び出し（`ls C:\x`・`git status --short` など）、`git log` / `git branch` / `Get-ChildItem`、`cat` / `type` / `Get-Content` / `git diff` / `git show` / `npm` / `npx` / `node` / `python` などからは作らない。
    - 綴りが大文字小文字を除いて一覧と同じときだけ作り、ルールには一覧の綴りを使う。`git.exe` / `ls.cmd` のような拡張子付き・版番号付き・引用符付きの名前からは作らない。
    - 複数のコマンドをつないだもの（`;` / `&&` / `||` / `|` / `&` / 改行 / `$(` / バッククォート）や、リダイレクトを含むものからは作らない。
  - Read / Grep / Glob: 対象のフォルダー以下の `Read` にする。例えば `C:\dev\foo\a.ts` を読んだなら `Read(//c/dev/foo/**)`。Grep / Glob は `path` のフォルダーを使う。
  - Edit / Write / MultiEdit / NotebookEdit: 対象のフォルダー以下の `Edit` にする（例: `Edit(//c/dev/foo/**)`）。
  - WebFetch: URL のホストに絞った `WebFetch(domain:<ホスト>)` にする。ホストに `*` を含むもの・IPv6 の `[::1]` などからは作らない。ツール全体の `WebFetch` は作らない。
  - MCP のツール: 名前から読み取り専用と分かる個別のツールだけ、ツール名のルールにする（例: `mcp__github__get_issue`）。ツール名（頭にサーバー名が付いていれば除く）を語に分け、最初の語が `get` / `list` / `read` / `search` / `find` / `describe` / `view` / `show` で、`create` / `delete` / `send` / `download` / `or` / `and` などの書き込みの語を含まないもの。
  - それ以外のツールからは作らない。
- 次のものもルールを作らず、理由を返す。
  - 複数のコマンドをつないだもの（`;` `&&` `||` `|` `&` 改行 `$(` バッククォート）、リダイレクトを含むもの。
  - パスが読み取れない・相対パス・`..` や特殊文字を含む・浅すぎる（`C:\` や `C:\dev` 直下）・ホームフォルダーそのものかその親、のどれかに当たるもの。
- **deny に当たるものは追加しない**。`channel-settings.json` と作業フォルダーの `.claude/settings.json` / `settings.local.json` の deny と照合し、当たったら当たった deny を返す。確認したあと、追加する直前にも読み直して照合する。照合の細かい規則は Slack 版と同じ。
- `!rules` と送ると、追加したルールを一覧する。「🗑 消すルールを選ぶ」のメニューで選ぶと消せる（次に再起動したときから反映。`!restart` を含む）。一覧のメニューの有効期限は10分。
- 前の版で足したルールのうち、今の方式では作れないもの（`Bash(git log:*)`・`PowerShell(npm.cmd:*)`・ツール全体の `WebFetch` など）は、起動のたびに allow に入れずに外し、Discord とターミナルに一覧を出す。`allow-extra.json` は書き換えないので、更新したら `!rules` で確かめて消す。
- 追加と削除はログ（`許可リストに追加` / `許可リストから削除`）に残る。

## このセッション中は全部許可（🔓）

`.env` に `SESSION_ALLOW_ALL=on` を書いたボットだけ、実行許可のカードに **🔓 このセッション中は全部許可** ボタンが出る。
押すと今回を許可したうえで、以後の実行許可にはブリッジが自動で allow を返す（カードは出さない）。

- 次のファイルの ask に当たる操作は自動許可から外し、今までどおりカードで確かめる。
  - `channel-settings.json`（`-SettingsFile` で渡したもの）
  - 作業フォルダーの `.claude/settings.json` / `settings.local.json`
  - managed settings（組織の管理設定）の `managed-settings.json` と `managed-settings.d\*.json`。Windows では `C:\Program Files\ClaudeCode` と、古い版の置き場所の `C:\ProgramData\ClaudeCode` の両方を読む（版ごとの置き場所は確かめていないので、どちらに在っても読む）。
  - これらのどれかが読めない・JSON でないときは、何を外すべきか判断できないので、全部許可のボタンを出さない。
  - レジストリ（`HKLM\SOFTWARE\Policies\ClaudeCode` など）やサーバーから配られる managed settings は読まない。組織がそれらで ask を配っている PC では、`SESSION_ALLOW_ALL` を使わない。
- deny に当たる操作は、Claude Code が確認を出す前に止める。だから全部許可の間も実行されない。
- ask との照合は次のとおり。判断できないものは、安全側に倒して当たると判定する（確認が出るだけ）。
  - ツール全体のルールは、そのツールのすべてのリクエストに当たる。`mcp__<サーバー>` と `mcp__<サーバー>__*` は、そのサーバーの全ツールに当たる。
  - シェルの中身付きのルールは、コマンドを `;` / `&&` / `||` / `|` / `&` / 改行 / `$(` / バッククォートで分け、どれかの部分にそのプレフィックスの語の並びがあるときに当たる（例: `Bash(git push:*)` は `cd repo && git push` にも `echo git push` にも当たる）。
    語はバックスラッシュを取り除き、コマンド名は小文字にして末尾の `.exe` / `.cmd` などと版番号を剥がして比べる（`git.exe push`・`git pus\h` も当たる）。PowerShell の別名（`rm` / `del` / `mv` / `cp` / `sc` など）は本来のコマンドレットに直して比べる（`PowerShell(Remove-Item:*)` は `del x` にも当たる。Bash の `rm` も `Remove-Item` とみなす）。行の継続（`\` + 改行、バッククォート + 改行）は、つないでから分ける。
  - 次のものは、コマンドの組み立てを解釈しないので当たると判定する。
    - 引用符（`"` / `'`）・バッククォート・波かっこ・丸かっこを含むコマンド（`git "push"`、`if ($true) { git push }`、`(git status)`）
    - 制御構文の語（`if` / `then` / `for` / `foreach` / `while` / `do` / `try` など）や、スクリプトブロックを取るコマンドレットとその別名（`ForEach-Object` / `%` / `Where-Object` / `where` / `?`）を含むコマンド
    - 部分の先頭が環境変数の代入（`FOO=1 git push`）、ラッパー（`sudo` / `env` / `sh` / `cmd` / `powershell` / `Invoke-Expression` / `Start-Job` / `runas` / `npx` など）、パスで始まる語のもの
    - コマンド名の後ろがオプション（`git -C x push`）か、展開で変わりうる語（`git $x`・`git pu*`）のもの
  - `Read` / `Edit` の中身付きのルールは、パスがそのフォルダー以下（`//`・`~/`・`./`・`/` 基準）のときに当たる。ファイル名だけのルール（`.env`・`*.pem`）なら、名前が一致するときに当たる。
  - 判断できないもの（コマンドやパスが読めない、途中にワイルドカードがあるパターン（シェル・パスとも）、ほかのツールの中身付きのルール、形の読めないルール）も当たると判定する。
- 自動で許可した操作は、最後に話しかけた場所に「🔓 自動許可: ツール名」と入力の先頭を残す。
- 解除されるのは、`!lock` を送ったとき、`!clear` などで新しい会話になったとき、ブリッジが終了したとき（再起動・`!restart` を含む）。`/compact` では解除しない。
- `!status` に「全部許可: 有効（○時から）／無効」を出す。

> Discord のアカウントを乗っ取られると、有効な間は ask と deny 以外の操作が確認なしで実行される。自分だけのサーバーで、手元のセッションに限って使う。

## ターミナル画面の確認と選択

Claude Code がターミナル側の選択画面（Discord に中継されない案内など）で止まったときに、Discord から画面を確かめて選択肢を選べる。

- `!screen` と送るか、警告や通知の **🖥 画面を確認** を押すと、ブリッジがターミナルの画面を読む。`!screen` は Claude には渡さない。
  - 選択画面（`>` / `❯` の付いた選択肢）なら、選択肢をメニュー（「選ぶ」）で出す。選ぶと、その選択肢までカーソルを動かして Enter を送る。
  - 選択画面でなければ、画面の末尾をコードブロックで送る。トークンらしき文字列は伏せる。
- 送れるのは、**選択肢を選ぶキー操作（↑ / ↓ / Enter）だけ**。自由な文字は入力できない。
- 選ぶと画面を読み直し、見せたときと同じ選択画面のままのときだけキーを送る。画面が変わっていたら何も送らない。メニューの有効期限は5分。
- 画面の読み取りとキーの送信は、`scripts\console.ps1` を子プロセスで実行して行う（ブリッジは Claude Code と同じコンソールを使っている）。
  Windows 以外の環境や、スクリプトが見つからないときは使えない。

## 状態の確認（`!status`）

「返事が来ない」ときに、まず見るもの。`!status` と送ると、次を返す（Claude には渡さない）。

- 稼働開始の時刻と経過時間、作業フォルダー、Discord の接続状態
- Claude への返事を待ち始めた時刻
- 回答待ちの実行許可の件数
- 「全部許可」の状態（有効にしたボットだけ）
- キャッシュのつなぎ止めの状態
- 直近の hook 5件

## 作業の中断（`!stop`）

Claude が見当違いの作業を始めたときに、手元に行かずに止めるための機能。ターミナルに Esc を1回送る。

- 応答中なら、Claude Code はその応答を打ち切って次の指示を待つ。ターミナル側で確認が開いていたら、その確認も拒否になる。
- 送ったあと「⏹ Esc を送って中断した」と返し、無応答の警告と「入力中…」を止める。
- 会話は残る。続けて別の指示を送ればいい。

## キャッシュのつなぎ止め（keepalive）

Claude Code のプロンプトキャッシュは、最後に使ってから1時間で切れる。切れたあとに話しかけると、会話全体を書き直す分の使用量がかかる（キャッシュを読むだけのときの約20倍）。
そこで、Claude が最後に応答を終えてから55分たったら、ブリッジが短い合図を1回送ってキャッシュを延ばす。Claude は合図にツールを呼ばず「ok」とだけ返す。

- 既定で有効。`.env` で変えられる。
  - `KEEPALIVE=off` で無効にする。
  - `KEEPALIVE_AFTER_MIN`: 送るまでの分数（既定 55）。
  - `KEEPALIVE_MAX`: 最後の会話から送る回数の上限（既定 6。書き直し1回は合図約20回ぶん）。
  - `KEEPALIVE_QUIET`: 送らない時間帯（既定 `01:00-07:00`。空なら時間帯なし）。
- 応答中・返事待ち・実行許可の回答待ちの間と、使用量の上限に当たっている間は送らない。
- Discord から話しかけるか、新しい会話が始まると、回数を数え直す。
- `!keepalive` で状態（次に送る時刻と回数）を見られる。`!keepalive off` / `!keepalive on` で切り替えられるが、起動し直すと `.env` の設定に戻る。
- 応答の終わりを hook で知るので、hook が動いていないと送らない。

## セッションの再起動・圧縮・クリア（`!restart` / `!compact` / `!clear`）

手元に行かずにセッションを立て直すための機能。channel のプロトコルには Claude Code にコマンドを送る手段が無い。
そこで、ターミナルの入力欄に**決まったコマンドだけ**を打ち込む（`!screen` と同じく `scripts\console.ps1` を使う。自由な文字は入力できない）。

- `!restart`: 状態ディレクトリに再起動フラグ（`restart.flag`）を置き、入力欄に `/exit` と Enter を送る。
  claude.exe が終わるとブリッジも終わり、`start.ps1` がフラグを見て再起動する。起動時の警告ダイアログには `dialog-answer.ps1` が答える。
  - 会話は引き継ぐ。フラグには、ブリッジが hook の記録から知った今の会話の `session_id` を書き、`start.ps1` は `--resume <session_id>` でその会話を開く。
  - id が分からないときや、その会話の記録（`~/.claude/projects/*/<session_id>.jsonl`）が無いときは、新しい会話で起動する。
  - `--resume` で起動して30秒以内に失敗で終わったときは、新しい会話で1回だけ起動し直す。Discord から戻せなくならないようにするため。
  - 次のメッセージは、「🟢 Claude Code のセッションを開始した」が出てから送る。20秒たっても claude.exe が終わらなければ、その旨を通知する（再起動フラグは残すので、遅れて終わればそのまま起動し直す）。60秒たっても終わらなければ、ブリッジが再起動フラグを消して、その旨を通知する（残すと、後で手元で終了したときに勝手に起動し直すため）。起動し直すなら、改めて `!restart` か `!restart force` を送る。
- `!restart force`: `/exit` を送らずに claude.exe を強制終了する。ターミナルが応答中のときや、画面が読めないとき用。
  - `taskkill /T /F` で、claude.exe の子プロセス（ほかの MCP サーバー、Bash の子など）もまとめて止める。親が `claude.exe` / `node.exe` でなければ止めない。手で起動したシェルを巻き込まないため。
  - 会話の記録は逐次保存されているので引き継げる。ただし直前の応答は失われる。
- `!compact`: 入力欄に `/compact` と Enter を送る。終わると hook が「🧹 会話を圧縮した」を通知する。
- `!clear`: 入力欄に `/clear` と Enter を送る。会話は捨てられ、新しい会話になる。元には戻せないので、残したい文脈があるなら `!compact` を使う。
- `/exit`・`/compact`・`/clear` は、画面が**空の入力欄で待っているときだけ**送る。応答中・選択画面・打ちかけの文字があるときは送らず、その旨を返す。
- 自動応答は、画面にタイトルの `development channel` と選択肢の `local development` の両方が出たときだけ答える。Claude Code の版で文言が変わって動かなくなったら、`start.ps1` の `$DevChannelDialogPattern` / `$DevChannelChoicePattern` を直す。

## Claude Code 側の出来事の通知（hook）

Discord からは見えない Claude Code 側の出来事を、Claude Code の hook を通して Discord に通知する。主な狙いは、使用量の上限とターミナル側の入力待ちに気付くこと。
通知は種類で色を分けたカードで出す（応答の失敗は赤、入力待ちや上限の案内は黄、セッションの開始は緑、圧縮とクリアは青、終了は灰色）。

- 起動スクリプトは、`--settings` に渡す設定へ hook を注入する。hook は `dist\src\hook.js` を実行し、状態ディレクトリの `hooks.jsonl` に1行追記するだけ。
  ブリッジは1.5秒ごとに増えた分を読んで、Discord に出す。MCP の stdout は MCP 専用なので、hook はブリッジと直接はやりとりしない。
- `start.ps1` は起動ごとに一意の値を環境変数 `DISCORD_CHANNEL_SESSION_TAG` に入れ、hook はその値を行の `session_tag` に記録する。
  ブリッジは自分と同じ値の行だけを扱う。同じ状態ディレクトリを使う別のセッションの出来事を、混ぜないため。
- 通知の宛先は、最後に話しかけられた場所。まだ話しかけられていなければ、許可ユーザー全員の DM。
- 通知するものは次のとおり。
  - ターミナル側の入力待ち（Discord に中継されない許可の確認、elicitation、サブエージェントの質問）。**🖥 画面を確認** ボタンを付ける。Discord に中継中の許可があるときは、重ねて出さない。
  - Claude が Discord に返事をしないまま応答を終えた（`Stop`）とき、または入力待ちのまま止まっている（`idle_prompt`）とき。Discord への返事を待っているときだけ出す。
  - 応答の失敗（`StopFailure`）。使用量の上限（rate limit）・混雑・認証・請求などの種別と、あれば詳細を添える。
  - 使用量の上限からの自動再開の案内（`quota_auto_resume_*`）。
  - セッションの開始（作業フォルダー付き）・終了・会話のクリア・圧縮。`/clear` のときは終了を出さず、「会話をクリアした」だけを出す。
- `node` が PATH に無いと、hook は注入されない（起動スクリプトが警告を出す）。通知が出ないときは、`hooks.jsonl` に何が記録されているかを見る。

## セッションを並べる

プロジェクトごとに作業フォルダーや権限を分けたいときは、セッションをもう1つ並べられる。その場合は、**ボットも別に作る**。
同じトークンで Gateway に2本つなぐと、同じメッセージが両方のセッションに届いてしまう。公式の Discord プラグインと同じボットを同時に使うのも、同じ理由で避ける。

1. 2つ目のボットを、README の「Discord のボットを作る」と同じ手順で作る。名前は変えておく。
2. 別の状態ディレクトリ（例: `%USERPROFILE%\.claude\channels\discord-app2`）に、そのボットの `.env` と `access.json` を置く。
   `access.json` の `channels` には、そのセッションで使うチャンネルだけを書く。既定の場所の外に置くなら、deny も足す（[権限の設計](security.md#権限の設計)）。
3. `-StateDir` と、必要なら `-SettingsFile`（相対パスはリポジトリ基準）を付けて起動する。
   ```powershell
   scripts\start.cmd C:\path\to\app2 -StateDir "$env:USERPROFILE\.claude\channels\discord-app2" -SettingsFile C:\path\to\app2-settings.json
   ```

- 状態ディレクトリの中身（`.env`・`access.json`・ロック・`allow-extra.json`・ログ）は、セッションごとに分かれる。ブリッジには、`mcp.json` の環境変数で状態ディレクトリを渡す。
- 一時ファイルは `%TEMP%\claude-discord-channel\<状態ディレクトリ名>\` に分かれる。`claude.exe` のコマンドラインにこのパスが入るので、どのセッションかを見分けるのにも使える。
- 設定ファイルを作業フォルダーの中に置くなら、その場所の `Edit(...)` を deny に入れておく。Claude が自分で設定を書き換えて権限を広げられないようにするため。
- Slack 版と Discord 版を1つのセッションで同時に使うのは対象外。それぞれの `start.ps1` で別のセッションを起動する。
